# 掌机：卡文件里的 Game Boy 模拟器

> 位于 `experimental` 分支，不包含在 `full` 中。

目的：展示卡文件的扩展性。整个模拟器（Peanut-GB 核心加相机接管代码）是 `WL.PATCH` 里一段约 29 KB 的 C 代码块，常驻 EG 不变、不重刷；拔卡或换回普通卡文件，相机就回到原样。

## 用法

1. 用 `tools/build_card.py --patch-only --menu-tab --preset full handheld` 按相机上的常驻 EG 打卡文件，把 `Z30/WL.PATCH` 放到卡上。
2. 可选：把自己的 GB 游戏放成 `Z30/GAME.GB`（只支持 DMG 黑白游戏，最大 4 MB）。没有这个文件时运行内置演示。
3. 菜单第 8 个标签 → 掌机（Handheld）→ 开始游戏。

| 行 | 内容 |
| --- | --- |
| 开始游戏 | 第一次读入 `GAME.GB`（有 `GAME.SAV` 且大小对就读入存档），全屏运行；暂停后再按是继续 |
| 状态 | 错误信息；运行过后显示上一次的帧率和 CPU 占用（`60fps cpu 35%`，内置演示前面加 `Demo`） |
| 按键 | 上一次运行的按键诊断：`R` 原始键码、`E` 事件、`O` 最后一个没有接管的事件；结尾 `K` 表示用键盘快照判断松开（后面是见过的位图），`B` 表示用空闲码 `0xBB` 判断，`P` 表示两者都没见到、按 250 ms 脉冲松开 |
| 保存进度 | 把卡带 RAM 写到 `Z30/GAME.SAV`（目前只有手动保存） |

游戏中：

- 多重选择器是十字键，OK 是 A；
- 画面左右两侧是触摸区：左边 SELECT / B，右边 START / A / B，按住时高亮；
- 按 MENU（或任何离开页面的操作）暂停；
- 拨盘被吞掉，避免像 Doom 早期那样一转就退出菜单；
- 没有声音。

内置演示（`tools/make_handheld_demo.py` 手写的约 600 字节 SM83 程序，没有任何第三方 ROM 数据）：网格上的 "Z30"，十字键滚动画面，按住 A / B 换调色板，START 复位。

## 实现

| 部分 | 位置 |
| --- | --- |
| 模拟器与相机接管 | `modules/handheld/handheld.c`，位置无关、无重定位（`build.sh` 检查），`tools/build_handheld.py` 生成 `features/experimental/handheld_payload.py` |
| 模拟器核心 | `modules/handheld/peanut_gb.h`（Peanut-GB，MIT，见文件头） |
| 菜单页 | `features/experimental/handheld.py`，页号 976，文字槽 14–19、54–55；框架里新增按行指定值列（`VALUE_SLOTS`） |
| 预设 | `handheld`，在 `EXPERIMENTAL_FEATURES`，不在 `full` |

相机接管照搬 Doom 菜单游戏 v8（`analysis/doom`）已经摸清的做法：

- 原厂菜单定时器第 45 号槽，周期参数 28，每次按真实经过的时间补帧（最多 3 帧、最多 18 ms），跟不上就降帧，不占死菜单任务；
- 最后一行的行控件（原厂绘制函数 `0x104B3855`）的绘制回调换成我们的：先画原厂内容，再用 `vgWritePixels` 写整屏缓冲（256 字节对齐），`vgFinish` 后才释放缓冲；
- 包装 AppMenu 5 个输入模式回调：键码经 `0x1045933F` 换成事件，上下左右 / OK 接管；空闲码 `0xBB` 或键盘快照为零时松开；触摸记录经原厂坐标换算后按区域映射；
- 页面离开回调里归还输入指针、定时器、绘制回调、页面回调表和元数据。

和 Doom 的差别：Doom 用页面控件 `+8 == 79` 判断控件，那其实是控件在页面上的序号（这一页是 `0x10 + 行号`）；`+12` 是文字类型，英文 2、中文 3（2026-11-26 实机中文界面报 `Page busy 1` 就是因为只认了 2）。现在只按原厂行绘制函数 `0x104B3855`（或游戏运行时我们的绘制函数）认这一行。`Page busy` 后面的数字：1 没拿到当前页，2 绘制函数不是原厂的，3 行数不对，4 找不到最后一行控件，5 页面结构不完整。

## 验证

- 主机（WSL gcc）：Peanut-GB 跑内置演示，按右、A+上、START 的画面变化正确。
- QEMU（`tools/probe_handheld_qemu.py`，先 `--prepare` 再在 WSL 里运行）：在原厂固件上按卡加载器的方式把 `full handheld` 的 `WL.PATCH` 装进原厂内存池（`0xC2C30000`，与相机上的位置同一区域），然后：
  - 第 8 个标签进根页，掌机页 4 行文字正确，状态 `Ready`；
  - 开始游戏后页面保持、定时器持续推进；合成的 720×480 画面中间是 GB 调色板的演示画面，两侧是触摸区；
  - 按住右侧 A 区：调色板反转、A 区高亮；松开恢复；
  - 打开设定菜单离开页面：5 个输入指针还原为原厂值，再进页面显示暂停后的状态。
  - 英文和简体中文界面各跑一遍都通过。
  - **QEMU 的 GPU 模型不会完成 `vgWritePixels`**（图形任务一直等待），所以探针打开测试开关 `skip_vg`，检查的是合成好的屏幕缓冲，不是显示输出。QEMU 的帧率和 CPU 数字也没有意义。
- 单元测试：`test_menu_framework`、`test_card`、`test_card_loader` 通过。
- 实机：**未验证**。要看的是：画面是否显示、十字键 / OK / 触摸是否可用、松开是否正常（"按键"一行结尾的 K / B / P）、MENU 退出后能否正常拍照、帧率和 CPU 占用。
