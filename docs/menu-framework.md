# 扩展菜单框架与快门声音分离（2026-11-24）

以前所有带菜单页的功能（画幅、斑马纹、码率、日期水印、竖拍、NEF 菜单、陀螺仪、3D 跟踪、对焦框颜色）都建在 `shutter_sound.add` 里，单选其中任何一个都会带上快门声音。现在菜单框架是独立模块，声音变成它的一个可选部分。

## 结构

| 文件 | 内容 |
| --- | --- |
| `features/menu/framework.py` | 设定菜单入口行、根页、错误弹窗、照片和视频菜单的直达行、状态块、各页注册与路由钩子（row / getter / route） |
| `features/menu/ui.py` | 框架函数的代码：`get`、`cas`、`open`、`ensure`、`labels`、`render`、`action`、`getter`、`route`、`show_error`、`page_return`、`dismiss_error` |
| `features/menu/tab.py` | 可选：扩展菜单作为菜单左侧第 8 个标签（见下文） |
| `features/sound/shutter_sound.py` | 可选的声音部分：函数槽、文字、文件页和开关页、`WL-SOUND.CFG`、声音钩子（shot / config / data） |
| `features/sound/ui.py` | 声音页的代码片段，由框架在 `sound=True` 时拼入 |
| `features/sound/audio.py` | WAV 读取与校验、播放钩子 |

- `build.py` 的 `MENU_FEATURES` 列出有菜单页的功能。选了其中任何一个，或选了 `shutter-sound`，就会带上框架；声音只在选了 `shutter-sound` 时才有。
- `shutter_sound.add(plan, ...)` 保留为旧入口，等于 `menu_framework.add(plan, sound=True, ...)`，研究工具仍可直接调用。
- 构建报告：框架信息在 `features.menu_framework`；带声音时 `features.shutter_sound` 指向同一份报告，并额外带上声音的字段。验证工具都改为读 `menu_framework`，声音自己的工具除外。

## 不带声音时

- 根页只列功能页，入口名为"扩展功能 / 自定义菜单"。没有声音分组页，没有文件页和开关页。
- 状态块里不再有约 225 KB 的 WAV 和 PCM 缓冲：弹窗紧接在框架头部和根页之后（偏移 128），功能页从 172 开始。单个功能约 263 字节，七个菜单页全选约 12.5 KB。
- 不安装声音钩子，只保留 3 个菜单钩子。
- 错误弹窗的文字表仍有 9 项，声音专用的几项是空串，"设置未保存"保留。

## 子页面从第一行打开（2026-11-24）

实机反馈：打开扩展菜单的子页面时，高亮显示的行和实际选中的行有时不一致。

- 原因：页面对象常驻在状态块里，它的列表光标（`+22`）和首个可见行（`+24`）会保留上次离开时的值。各子页的 `*_open` 只把焦点设到当前值那一行，没有重置这两个值，所以相机按一种状态画列表、按另一种状态判断选中行。根页的 `open` 早就会清零它们，所以根页没有这个问题。
- 修改：`menu_ui.list_top()` 在打开前清零这两个值。画幅、斑马纹、码率、日期水印、NEF、陀螺仪、竖拍、3D 跟踪、对焦框颜色这 9 个页面，以及声音的开关页和文件页，现在都从第一行打开，焦点也在第一行；当前值仍由右侧的 `*` 标出。
- 日期水印在改颜色或光晕后会在原页重开，焦点留在刚改的那一行，这一段不变。
- 这个修改会改变所有带菜单的构建，包括 `full`。`tests/test_nef_ui.py` 已改为检查从第一行打开、光标清零。
- QEMU（新的 `full`）：斑马纹、码率（5 例）、画幅（7 档）、日期水印（繁体）、陀螺仪、原生直达行（简体）都通过，固件版本页也能打开。2026-11-24 实机（`output/card-v3-menutop`）：用户确认高亮与选中行一致，问题已解决。

## 根页分类（2026-11-25）

用户反馈根页太杂，方案见 [menu-layout.md](menu-layout.md)。这是其中第 1 步：根页不再平铺功能页，改成分类。

| 根页行 | 分类页 | 页号 | 成员 |
| --- | --- | --- | --- |
| 拍照 | 是 | 970 | 照片画幅、照片高光显示、日期水印、NEF 压缩 |
| 对焦与显示 | 是 | 971 | 3D 跟踪、对焦框颜色、竖拍显示 |
| 视频 | 是 | 972 | 视频码率、Gyro 电子减震 |
| 快门声音 | 原有的声音分组页 | 962 | 开关、选择声音 |
| 实验 | 是 | 973 | 模块宿主（研究构建） |

- 规则在 `menu_framework.CATEGORIES` / `root_layout()`：构建里没有成员的分类不出现；只有一个成员的分类直接把这个功能放在根页；整个根页只剩一个分类时，根页直接列它的成员。所以单选或只选两三个功能时，根页和以前一样。
- `full` 的根页从 8 行变成 4 行。3D 跟踪和对焦框颜色以前只能从照片菜单的直达行进入，现在也在"对焦与显示"里。
- 分类页的每行右侧显示该功能的当前值（就是以前根页右侧的值）；根页上的分类行没有值列。
- 分类页的标题用文字槽 173～176（`BLOCKS['category']`，以前的空闲块）。新词"拍照、对焦与显示、视频、实验"（繁体"拍照、對焦與顯示、影片、實驗"）的字都在扩展字库里，不用重刷常驻 EG。
- 分类页对象在状态块里，每页 44 字节，排在声音分组页之后；父页是根页。功能页的父页是它的分类页，所以返回键和确认选择（`page_return`）都回到分类页。从分类页打开功能页时会重新写一次父页，因为照片菜单的直达行会把它改成标签容器。
- 从根页进入分类页时，光标和首个可见行清零，焦点在第一行（和功能页一样）。
- 构建报告：`menu_categories` 仍是根页各行（键可以是分类）；新增 `category_pages`（页号、偏移、标题槽、成员）和 `menu_paths`（每个功能页从根页起要激活的行，每一步的页、行、控件 ID 和打开的页）。QEMU 工具用 `tools/menu_path.py` 按 `menu_paths` 进入分类页，再把分类页当作"根"继续原来的检查。
- `full` 的字节变了，这是预期的。

## 状态页（2026-11-25）

方案第 2 步：根页第一行"状态"，右侧显示"正常"或"需检查"。进入后只显示信息，没有能打开功能页或改设置的行（按确定没有动作）：

| 行 | 内容 | 来源 |
| --- | --- | --- |
| 卡文件 | 已加载 / 需检查；闪存构建为"固件内置" | 加载器状态字 `0xC1832D30` 的低 16 位等于 `0x8100`（完成且代码 01）为已加载 |
| 版本 | 构建标记，`build_card.py` 默认是"月-日 git 短哈希"，有未提交改动时加 `+`；`--build-tag` 可指定；闪存构建为 `dev` | 构建时写入的文字 |
| 功能 | 这份卡文件包含的功能数，如"16 项" | 构建时写入 |
| 设置 | 已保存 / 未保存 | 本次开机有设置保存失败（`RESULT` = 8 进入 `show_error`）就置一个标志，到关机为止 |

- 第一版还有"加载器"（常驻 id）和画幅、NEF 压缩、日期水印、视频码率四个当前值。用户觉得状态页不应该有能改设置的地方，所以去掉了四个值行（它们会打开功能页，当前值在分类页里也能看到）；常驻 id 也去掉了（卡文件能加载就说明 id 匹配）。
- 卡文件不是正常加载（实际只可能是 `S=0E`）或设置没保存上时，根页显示"需检查"。
- 页号 974，状态块里 48 字节（页面对象加标志）。文字槽：187–188、211–214、252–255（以前空闲）。
- 实现：`menu_framework.STATUS_*`、`menu_ui` 里的 `status` 段（标签文字和判断都在 `labels` 里，跟着每次绘制更新）。
- **字形问题**：常驻 id 那一行最早叫"常驻固件"（后来改叫"加载器"，现在已去掉）。"驻"不在原厂简体字库里，要从扩展字里补；补上之后，QEMU 里简体字库的"画"在所有页面都画不出来（"照片画幅"变成"照片 幅"，原厂照片菜单里的直达行也一样），文字槽里的字符串是完好的。改成全用原厂字的名字后恢复。我们的解析器读这个扩展字库没有问题，原厂字体引擎为什么丢字还没查清。`tests/test_menu_framework.py` 现在固定了两个字库各补多少个字，以后加文字要么只用原厂字，要么在 QEMU 和实机上把各页都看一遍。

验证：
- 单元测试：状态页是根页第一行、四行的顺序和功能数、没有一行会打开别的页、文字槽不和原厂冲突。
- Unicorn（`verify_menu_categories.py`）：状态页的系统行按确定没有动作；值行打开对应页、父页是状态页，再从原来的路径打开时父页改回；`show_error` 遇到 `RESULT` = 8 时置标志。
- QEMU（`verify_menu_categories_qemu.py`）：简体、繁体、英文、第 8 个标签都通过：系统行文字正确，4 个值行打开再返回，置标志后根页显示"需检查"、设置行显示"未保存"。改名后简体的"照片画幅"恢复正常。旧工具（陀螺仪、高光显示、画幅、日期水印、码率、直达行）改为经分类页进入后都通过。
- 卡文件分支（读加载器状态字）只能在实机上看。

## 菜单左侧第 8 个标签（构建选项 `menu_tab`，2026-11-24）

用户反馈扩展功能的入口太杂、不好找，所以把扩展菜单做成菜单左侧标签栏的第 8 个标签。目前是选项：`build(..., menu_tab=True)`，卡文件用 `tools/build_card.py --menu-tab`。默认关闭，默认构建与以前逐字节相同。GUI 打包程序总是打开它（2026-11-25，见下文“总带状态页”）。实机：2026-11-24、11-25 两次上机发现的按键和色条问题已修正（见下文）；2026-11-25 在 `output/card-banner-v1-categories` 上确认第 8 个标签能进入根页和分类页（见[根页分类](#根页分类2026-11-25)）。研究过程见 [menu-tab-research.md](menu-tab-research.md)。

| 部分 | 做法（`features/menu/tab.py`） |
| --- | --- |
| 标签 | 标签栏（原厂页 1）的页面描述改为 8 行，每格 64×52；加第 8 个控件、第 8 张事件表（复制设定标签的），"标签 → 页号"表加入 955 |
| 按键 | 设定标签的事件表里有 4 个事件进入设定页：右键 `0x256`、确定 `0x25B`、`0x26F`、`0x27E`（按键到事件的表在 `0x1073B400`：上 `0x253`、下 `0x254`、左 `0x255`、右 `0x256`、确定 `0x25B`）。原厂导航进不了页 955（焦点留在标签栏），所以这 4 个都改为调用框架的 `open`（和以前设定菜单那一行一样），目标 `0x3BB` 表示原地不动。触摸标签走别的路径，不经过这张表 |
| 色条 | 标签栏右边那条 3×480 的竖色条按标签行号从表 `0x10734D74` 取图（每项：色条、分隔线），第 8 行原厂是备用的浅灰色。复制这张表，第 8 行换成我们的青色色条（`platform/menu_tab_strip.png`，ID `0x15EB`），改它唯一的字面量 `0x1045DAEC` |
| 图标 | 自绘灯笼图标（和下面的色条一起由 `tools/build_tab_icon.py` 生成），5 种状态各一张 64×60 调色板 PNG（`tools/build_tab_icon.py` 生成，存在 `platform/menu_tab_icon_0..4.png`）。原厂图像表在只读区，所以给它唯一的读取函数 `0x104ED4E2` 挂钩：ID `0x15E6` 起的 5 张由我们的小表提供。原厂图标组表 `0x10734DB4` 复制一份，加第 10 组，两个引用它的字面量（`0x1045E958` 构建标签、`0x1045F2B0` 刷新标签）都改指副本 |
| 上次停留的标签 | 退出菜单时写 `0x3D07` 的地方挂钩：值 ≥ 7 存成设定标签（4），拔卡后原厂不会读到 7 |
| 根页 | 用设定菜单那样的顶层版式：标题居中，没有返回箭头；右上角放一个空文字控件（`0xA1A`），从功能页返回时把返回按钮按下的框盖掉 |
| 设定菜单入口 | 有了标签就不再加设定菜单里的"自定义菜单"一行 |
| 卡文件 | 标签栏在**每次按 MENU 打开菜单时**按页面描述重新建立，所以加载器在开机约 3 秒后才改也没关系，下次打开菜单就有第 8 个标签。页面描述按"表 → 行数"的顺序写，中途重建只会看到新表配旧行数 |

注意的地方：
- 只改一个字面量不够：原厂刷新标签时（右侧不是原厂标签页，比如在扩展页里）用的是另一个字面量，按控件 `+20` 取图标组。只改第一个时，第 8 个标签在普通状态下取到原厂表外的数据，显示为空白。
- 第一次上机（2026-11-24）：标签显示正常、触摸正常，但按确定进入的是设定菜单，右键没反应。原因是复制的事件表只改了右键 `0x256` 的目标（当时以为它是触摸），其余 3 个仍指向设定页；而右键改了目标也进不去页 955。
- 第二次上机（2026-11-25）：确定能进入、左键能返回；右键仍进不去；标签右边的色条是浅灰色，用户希望和图标的强调色一致（青色）。已改成上表的做法。
- 图标组不能用第 8 组（"最近的设定"）代替：刷新时普通状态会显示原厂的时钟图标。

QEMU（`tools/probe_menu_tabs_qemu.py`，`full` 加 `menu_tab`）：
- 8 个标签排列整齐；灯笼图标在普通（灰）、选中（黄）、当前（青）三种状态下都正确；"我的菜单"标签的原厂图标不变；
- 触摸第 8 个标签打开根页，根页标题居中、没有返回箭头；进功能页再返回，右上角没有残留；
- 焦点在第 8 个标签时发右键 `0x256`、确定 `0x25B`、`0x26F`、`0x27E`：都进入根页，标签和色条为青色、焦点在第一行；同样的右键和确定在设定标签上仍打开设定菜单（橙色色条）；
- 只用按键走一遍：第 8 个标签 → 右键进根页 → 右键进画幅页 → 左键回根页 → 左键回标签栏 → 上键到设定 → 右键进设定 → 左键回 → 下键回第 8 个 → 右键、确定都进根页，画面正常；
- 在功能页里触摸别的标签不起作用（功能页保持焦点），这时按右键是功能页自己的按键。这和标签无关，以前从设定菜单入口进入时也一样；
- 上下键 7 → 8 → 1 循环；停在第 8 个标签退出时存的是原厂标签值；
- `--late-meta`：菜单打开后才改页面描述（模拟卡文件加载）时，当前这次菜单保持原厂 7 个标签、操作正常；关闭后重新按 MENU，8 个标签和图标都出现，根页和功能页正常。
- 几次运行在按键步骤遇到 QEMU 偶发的 `T02` 停止，重跑通过。

### GUI 总带标签和状态页（2026-11-25）

用户要求 GUI 打包程序打出的卡文件总有第 8 个标签，即使所选功能都没有菜单页，也要有状态页。

- `gui.run_build` 总是传 `menu_tab=True`。命令行 `tools/build_card.py` 不变，仍要加 `--menu-tab` 才有标签。
- `menu_tab` 现在总会带上菜单框架（`build.py`），框架把它当作有分组（`grouped`），所以根页总有"状态"一行。只选 `focal-length`、`liveview-dual` 这类没有菜单页的功能时，根页只有"状态"；只选 `shutter-sound` 时，根页是"状态"和"快门声音"（以前不带状态页、根页直接列声音行）。
