# 胶片风格日期水印（`date-stamp`）

日期：2026-11-02。固件：Z30 C1.20。维护者反馈已上机测试，但各拍摄模式的具体结果尚未记录到本文。离线验证全部通过；下文“未验证”列出的三项判断只有真机能确认，在结果记录之前仍按未确认处理。该预设是实验性的，默认不含在 `full` 中，需要单独选择。

## 功能

在机内生成的 JPEG 右下角写入七段数码日期，样式仿胶片机数据后背的液晶字：数字右倾约 6°，每段两端削尖、段与段之间留缝。可选的柔光晕会在数字周围加一圈由外向内逐渐变亮的光，模拟 LED 透过片基曝光时的扩散。光晕只提亮比它暗的像素，所以在夜景、阴影等暗处明显，在天空等亮处基本看不出，这和真实胶片一致：

| 菜单选项 | 效果 |
|---|---|
| 关闭（默认） | 不改动任何像素 |
| 年 月 日 | `'26 11 02` |
| 年 月 日 时:分 | `'26 11 02 14:05` |
| 月 日 年 | `11 02 '26` |
| 日 月 年 | `02 11 '26` |
| 日 时:分 | `02 14:05` |
| 颜色 | 点一次换一种，停留在当前页：橙色、红色、黄色、白色。原厂中文字库没有“橙”“橘”，所以橙色在中文菜单里显示为“默认”（繁体“預設”） |
| 柔光（繁体“光暈”，英文 Glow） | 光晕开关：点一次在开启和关闭之间切换，停留在当前页；默认关闭。原厂简体字库没有“晕”，所以简体菜单写作“柔光” |

入口是 **照片拍摄菜单 → 日期水印**（列表末尾），或 **设置 → 自定义菜单 → 日期水印**。格式、颜色和光晕保存在 SD 卡根目录 `WL-STAMP.CFG`，开机后在首次打开日期水印直达行、进入自定义菜单或按下快门时恢复；文件缺失或损坏时保持关闭。颜色和光晕共用记录里的同一个字：低两位是颜色，第 3 位是光晕。旧版本写入的配置继续有效，恢复为原来的颜色、光晕关闭；第一版的配置恢复为橙色。开启光晕后保存的配置拿回旧版本固件会被当作无效记录，水印保持关闭。

字高约为 3:2 画面高度的 3%，按图像宽度等比缩放，主图和机内预览图各自绘制；宽度不足 696 像素的小图按 696 计算，字高约 14 像素，保证还能认出。字形在 42 行的网格上预先栅格化成按行合并的矩形段，缩放时换算的是每段的边界，所以相邻段之间不会出现缝隙或重叠。竖拍时水印跟随照片方向：数字转 90°，放在按 EXIF 方向转正后画面的右下角，离两条边的距离与横拍相同。方向取自拍摄信息 `+0x2615`，原厂 EXIF 方向标签读的就是这个字节（回调 `0x102D48E6`：1 写作 EXIF 8，2 写作 EXIF 6，其余写作 1），它与拍摄时间在同一个函数 `0x101D5F74` 里填好，所以水印方向与 EXIF 方向同源。2026-11-03 用户上机确认：向左、向右竖拍时水印都在转正后画面的右下角，方向正确（固件 `output/date-stamp-v5`，SHA-256 `d416ed82…a739`）。原厂不记录倒置，倒拿相机时水印与 EXIF 一样按横拍处理，这一情况没有单独上机记录。竖拍时短边可能放不下整行，例如 160×120 缩略图上的“年 月 日 时:分”，这时只跳过该图，不画半截。

构建：

```powershell
python patch.py date-stamp --source Z_30_0120.bin --output output/EG209020-stamp.BIN

```

## 实现

挂点是原厂 JPEG 编码入口 `0x10096EE6`。这里已有待编码的 Y/C 平面，编码器尚未启动，不必追踪传感器到编码之间的处理链。

1. 门控替换入口 10 字节，先比对返回地址。只有 `0x100A60F2` 这一步骤族的 5 个调用点（`0x100A6198`、`0x100A6304`、`0x100A6540`、`0x100A66AE`、`0x100A684A`）会进入绘制，因为它们调用时 `r4` 才是拍摄上下文。其他调用方和关闭状态直接执行被替换的原厂指令后回到 `0x10096EF0`。
2. 时间取拍摄信息 `[上下文+0x3A4]+0x2624`，布局为 `u16 年, u8 月, 日, 时, 分, 秒`。原厂 EXIF 日期写入函数 `0x102CDCBE` 读的就是这个结构，所以水印和 EXIF 时间同源。年份不在 2000–2099 或其他字段越界时跳过绘制，不会写出错误日期。
3. 绘制只读写水印所在的矩形（开启光晕时含留边）。平面由硬件写入，所以先逐行 invalidate，CPU 读写完再逐行 clean，每次请求都不超过一行，停留在原厂按行维护分支（上限 `0x45000` 字节），不触发整缓存服务。
4. 光晕关闭时只画一遍，按原色不透明地画数字。开启时共绘制五遍，前四遍是光晕：每个矩形段分别向外扩 7、5、3、1 个网格单位，颜色依次为原色的 14%、20%、28%、40%；某个像素的亮度低于这一遍的值时，提亮到这个值，并把它所在色度对的颜色换成光晕色，否则不动。最后一遍按原色不透明地画数字本身。两种写法都是“再做一次也不变”的操作，所以同一组平面被绘制两次，结果完全相同。

开启光晕时，全尺寸“年 月 日 时:分”在 Unicorn 中实测约 950 万条指令（“年 月 日”约 550 万条）、592 次缓存维护调用；640×480 缩略图约 19 万条。这比全尺寸 LUT（约 53 亿条指令）少约 500 倍，不会像 LUT 那样饿死处理任务，但比关闭光晕时多出不少，预计每张增加约十毫秒级的处理时间。关心连拍速度时可以关闭光晕。真机耗时尚未测量。

## 已验证（离线）

```powershell
$env:PYTHONPATH = 'src'
python -m unittest tests.test_date_stamp tests.test_presets tests.test_gui
python tools/verify_date_stamp.py --source Z_30_0120.bin
python tools/verify_date_stamp.py --source Z_30_0120.bin --preset full date-stamp --output build/research/date-stamp/verify-full.json
```

- **像素一致**：57 个帧用例（9 种尺寸 × 5 种格式，含格式 1/2 与行步长填充，光晕开关交替，方向在横拍、两种竖拍和未知值之间轮换；再加 4 种颜色 × 光晕开关各一例，以及全尺寸两种竖拍 × 两种色度格式），ARM 与主机参考逐字节一致，单独构建和 `full date-stamp` 都通过。背景亮度是覆盖 0–255 的斜向渐变，每种尺寸都确认光晕既提亮了较暗的像素，也保留了较亮的像素。
- **门控**：24 个用例。关闭、未知模式、未知样式、6 种非法日期、不支持的格式、放不下、框架未初始化、拍摄信息或平面为空、4 个其他编码调用方，全部不写像素、不调缓存；5 个调用点都会绘制；开或关光晕时重复绘制结果都不变。每个用例都检查寄存器、栈和被替换指令的执行结果。
- **缓存顺序**：所有写入都在全部 invalidate 之后、全部 clean 之前，并且落在被维护的缓存行内。
- **菜单**：15 个 Unicorn 用例（格式、颜色和光晕保存及全新内存恢复、第一版配置兼容、6 种坏记录保持关闭、颜色行原地循环、光晕行原地切换且换色时保留光晕、保存失败时保留当前选择并提示）；QEMU 原生菜单在简体中文、繁体中文和英文下都通过，覆盖触摸选择、返回、配置内容、`*` 标记和颜色行，并检查了三种语言的颜色行截图：改色后名称立即更新，缺字已排除。颜色行改完后会重新打开本页，因为列表控件只在重建时才显示新文字，只重绘或标脏都不够。
- **回归**：未选择 `date-stamp` 时，`full` 和 `photo-zebra` 的镜像 SHA-256 与改动前相同，已有构建不受影响。

这些检查替换了原厂缓存服务和状态读取，没有运行真实编码器、传感器或拍摄任务。

## 未验证

1. **真实拍摄是否走这条路径。** 依据：画幅功能经实机确认的裁切路径（`0x100A4E20`）同样使用拍摄上下文的 `+0x30C`、`+0x3A4`，而选表函数 `0x1021E2C8` 默认选中的表使用该步骤族。这是强静态证据，不是实拍证据。另有一族 `0x1009EF88` 由作业类型 `+0xD` 选表，用途未确定，目前直接放行。如果部分拍摄模式走那一族，这些照片不会有水印，但也不会受损。
2. **`+0x2624` 在编码时是否已填好。** `0x101D5C54` 在拍摄流程中写入，时序是静态推断。如果未填好，校验会跳过绘制，表现为没有水印。
3. **Cb/Cr 字节顺序。** 与 LUT 相同，仍按 Cb 在前假设。如果橙色水印显示为蓝色，说明顺序相反，在 `date_stamp.py` 的 `_ycbcr()` 中交换 Cb 与 Cr 即可，数字和光晕的颜色都由它算出。白色几乎不含色度，不能用来判断。

另有几点已知行为：

- NEF 原始数据不会被改动，但 NEF 内嵌的 JPEG 预览可能带水印，尚未确认。
- 开启时修饰生成的副本也走这条路径，会按原片时间再绘制一次。尺寸相同时结果不变；缩小尺寸的副本可能与缩小后的旧水印略微错位。需要干净副本时请先关闭水印。
- 水印写入像素，无法从 JPEG 中移除。原图没有未加水印的备份，正式拍摄前请先试拍。
- 时间取自拍摄信息，不读当前时钟，所以连拍积压时不应出现偏移（待实机确认）。

## 上机步骤

1. 刷入后用默认“关闭”拍一张 JPEG，确认能正常保存和回放。
2. 选 **年 月 日 时:分**，拍 JPEG L，用电脑查看右下角：应为橙色，时间与 EXIF 一致到分钟。再切换其他格式和颜色各拍一张，确认颜色名与实际颜色相符。再打开 **柔光**，对着暗处和亮处各拍一张：暗处的数字周围应有柔和的光晕，亮处应只有数字；关闭后暗处也应只有数字。
3. 依次确认 M、S 尺寸，4:3 等自定义画幅（水印应在裁切后的右下角内），回放缩略图。
4. 分别向左、向右竖拿相机各拍一张，在电脑和相机回放中查看：转正后水印应在右下角，数字正向可读（已于 2026-11-03 上机确认）。
5. 分别用机械快门和静音拍摄，单张和连拍各试一次，看连拍速度有无变化。
6. RAW+JPEG 和仅 RAW 各拍一张，确认 NEF 能正常打开，并记录内嵌预览是否带水印。
7. 关机重开后直接拍摄（不进菜单），确认设置已恢复。

| 现象 | 判断 |
|---|---|
| 没有水印，照片正常 | 走了另一族，或时间字段未填好；需要探针镜像区分 |
| 水印是蓝色 | Cb/Cr 顺序相反，改常量后重出镜像 |
| 水印有彩色杂边 | 记录照片尺寸与格式，核对色度采样 |
| 水印附近有错位色块 | 缓存维护有问题，立即停用并保留原片 |
| 拍摄卡死或 JPEG 损坏 | 立即刷回原厂或之前的镜像，记录拍摄模式和尺寸 |
