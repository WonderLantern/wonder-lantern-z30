# 胶片颗粒（`film-grain`）

日期：2026-11-25。固件：Z30 C1.20。**2026-11-25 用户上机测试，反馈都正常**（卡文件 `output/film-grain-v1/Z30/WL.PATCH`，`full film-grain` 加第 8 个标签，常驻 id `0x67f308e7`）。之后 `film-grain` 纳入 `full`，页面去掉了调试用的“上次耗时”一行，正式卡文件为 `output/film-grain-v2/Z30/WL.PATCH`（`full` 加第 8 个标签，同一常驻 EG）。机内菜单默认关闭。

功能移植自 [Wonder Lantern Z5 的 FILM](https://github.com/WonderLantern/wonder-lantern-z5/blob/main/docs/FILM_GRAIN.md)（A52，MIT，作者在 Z5 上实机通过）。颗粒场、强度曲线和逐字运算与 Z5 相同，同一档位在两台相机上的颗粒统计一致。

## 用法

扩展菜单 → 拍照 → **胶片颗粒**（繁体“膠片顆粒”，英文 Film grain）：

| 行 | 说明 |
| --- | --- |
| 风格 | 每按一次切换：关闭 → FUJI400 → HP5。FUJI400 参照富士 400 彩负扫描；HP5 偏黑白，颗粒更紧，可配合相机的“单色”优化校准 |
| 强度 | 每按一次切换：3 → 4 → 5 → 6 → 1 → 2。第 3 档是基准 |

- 设置存在卡根目录的 `WL-FILM.CFG`。开机后扩展菜单第一次初始化时恢复设置，在此之前颗粒是关的。这和日期水印的规则相同：开机后先进一次扩展菜单，再拍。
- 只改 JPEG 的亮度，不改色度。NEF 的传感器数据不改。
- 颗粒写进了 JPEG 像素，事后去不掉。正式拍摄前先试拍。

| 画质 | 加颗粒的图 |
| --- | --- |
| JPEG | 主图（全强度），以及三种预览（主图强度的 5/8） |
| RAW+JPEG | 只加主图。Z5 上 NEF 预览与主图共用同一个亮度平面，所以也会带颗粒 |
| RAW | NEF 内嵌的全尺寸预览 |

和日期水印一起开时，先加颗粒，再画日期，所以数字上没有颗粒。

### 挂点

挂点和日期水印相同：原厂 JPEG 编码入口 `0x10096EE6`，只处理拍摄步骤族的 5 个调用点。Z5 的代码注释里也把这个入口对应到它自己的 `0x1009F33A`。

- 同时构建日期水印时，日期水印的闸门先调用颗粒钩子，再画水印。
- 不带日期水印时，本功能自己装同样的闸门，只有颗粒。

颗粒钩子先通过菜单框架读状态：框架还没初始化，或风格是“关闭”时，马上返回。否则在栈上组一个调用块 `{参数块, 拍摄上下文, 返回地址, 状态, 表}`，交给 C 模块。

调用点与用途对应如下。顺序与 Z5 的 S1–S5 一致；每个函数的前置判断也一致：S1 先判断“有 JPEG”，S2 先判断“有 RAW”，S3 先判断“有 JPEG”。

| 返回地址 − 5 | 所在函数 | 用途 |
| --- | --- | --- |
| `0x100A6198` | `0x100A60F2` | JPEG 主图（平面来自 `ctx+0x30C`） |
| `0x100A6304` | `0x100A6260` | NEF 内嵌全尺寸预览（`ctx+0x310`，为 0 时用 `+0x30C`） |
| `0x100A6540` / `66AE` / `684A` | `0x100A64C4` / `65A6` / `6740` | 三种预览 |

画质取拍摄信息 `[ctx+0x3A4]+0x228`。原厂 `0x101D5AD0`（有 RAW：0、1）和 `0x101D5AE0`（有 JPEG：0、3）读的就是这个字节，取值与 Z5 的设置 `0x0501` 相同：0 = RAW+JPEG，1 = RAW，3 = JPEG。

### 写像素之前的检查（C 模块）

1. 描述符：格式 1 或 2；宽 16–8192，高 8–8192；行宽不小于宽度；亮度起点和行宽 4 字节对齐；亮度平面末尾不进入色度平面。
2. 处理器在 SVC 或 SYS 模式，MMU 开启，页表是短描述符格式。
3. 用 `ATS1CPW` 逐个 4 KiB 页查地址（期间屏蔽中断，查完恢复原来的中断状态）：
   - 不能有缺页；
   - 物理地址必须等于虚拟地址，因为编码硬件按这个地址读；
   - 不能是 device 或 strongly-ordered 内存。

   任何一项不符，整张跳过，照片保持原样。

| 结果码 | 原因 |
| --- | --- |
| 3 | 描述符不对 |
| 4 | 处理器模式或页表格式不对 |
| 5 | 有缺页，或物理地址不等于虚拟地址 |
| 6 | device 内存 |

平面的缓存属性目前不知道：Z5 实测是不缓存的普通内存，日期水印按可缓存处理。两种情况都支持：

- **不缓存**（`n`）：不做缓存维护。
- **可缓存**（`c`）：每行读之前调用 `0x10204B7C`（写回并作废），写完调用 `0x10204B0C`（写回）。每次请求都只有一行，不超过原厂按行维护的上限 `0x45000`。读之前用“写回并作废”，不用只作废：这样作废行首行尾那些不完整的缓存行时，不会丢掉别处的脏数据。

无论哪种，都按每 8 个字一组用 `LDM` 读到栈上，算完再用 `STM` 整组写回。Z5 测得逐字访问不缓存的平面要慢约 7 倍。

### 颗粒

- **颗粒场**：每种风格一张 256×256 的颗粒场（0–63，32 为零点），构建时用 Python 算好放进卡文件。两张颗粒场加 24 个 1024 项的查表，共 152 KiB。
- **每像素改变量**：`((颗粒值 − 32) × 步长 + 8) >> 4`，有符号饱和加到亮度上。
- **步长**：每 4 个相邻像素共用一个步长，用 `USAD8` 求和后查表得到。表按风格、档位、主图或预览各一张。
- **种子**：每张图一个，`(毫秒时钟 0xC18EB098) ^ 亮度地址 ^ 调用次数 × 0x9E3779B1`。每个 256×256 区域取自己的行偏移和列偏移，看不出平铺的重复。

## 诊断

正式版菜单不显示调试信息。C 模块仍把最近一张主图的结果写在菜单状态里，排查时可以读内存（偏移相对页面状态 `film_grain_control.state_offset`，见构建报告）：`+12` 结果码（1 成功，其余见上表），`+16` 耗时毫秒，`+20` 开机后加过颗粒的张数，`+24` 第一页的 PAR，`+32` 宽高，`+36` 调用点，`+40` 一行 ASCII 摘要（例如 `912 ms n #3`，`n` 不经缓存、`c` 经缓存）。

## 字库

“胶、颗、粒”（繁体“膠、顆、粒”）不在原厂字库里，两种构建的处理不同：

- **卡文件**：用常驻 EG 里已有的 GB2312 一级字和 Big5 常用字，不改字库。
- **整包**：只有选了 `film-grain` 才把这 6 个字补进字库（`plan.feature_labels`），不选的整包字库不变。

整包补字以后，QEMU 检查了简繁两种语言的分类页、语言页和固件版本页（字库规则见 [menu-framework.md](menu-framework.md) 状态页一节的字形问题）。“风格、强度”都是原厂字。

## 实机结果

2026-11-25 用户按下面的上机步骤测试，反馈都正常。测试用的卡文件页面上还有一行“上次耗时”：每张主图约 900 ms 到 1 s，用户记下的一次读数是 `990 ms n`（用户记录），与按 Z5 的 1.1 秒估算的约 1 秒相符。`n` 表示亮度平面不经缓存，和 Z5 实测相同：Z30 走不做缓存维护的那条路，按行写回和作废的分支在实机上没有用到。连拍时的等待没有测：每张多出约 1 秒在后台处理，按 Z5 的经验，低速连拍影响不大，高速连拍几张后就要等缓存清空，需要连拍速度时把颗粒关掉。之后按用户要求，正式版去掉了这一行（见下文“诊断”）。下面几项是测试前列出的疑问，留作对照。

## 测试前的疑问

1. **耗时。** Z5 每张 6016×4016 约 1.1 秒。Z30 主图 5568×3712，像素少约 14%，预计约 1 秒，但缓存和内存都不同。
2. **平面的缓存属性和地址映射。** 如果 Z30 的映射或执行模式和 Z5 不同，颗粒不会加上，但照片不受影响。
3. **NEF 预览是否与主图共用平面**（RAW+JPEG）。如果不共用，NEF 预览没有颗粒，JPEG 照常有。
4. **连拍。** 加颗粒期间相机在后台处理，Z5 上高速连拍 4 张后开始等待。

## 上机步骤

1. 把 `output/film-grain-v1/Z30/WL.PATCH` 放到卡上的 `Z30/`，开机，等就绪提示出现。
2. 扩展菜单 → 拍照 → 胶片颗粒：风格选 FUJI400，强度保持 3。
3. 只拍 JPEG，拍一张中间调为主的平坦画面（墙、天空）。
4. 在电脑上 100% 查看：中间调应有细小的颗粒团，暗部和高光较弱。
5. 依次试：HP5；强度 1 和 6；RAW+JPEG（JPEG 有颗粒、NEF 能正常打开，看内嵌预览有没有颗粒）；只拍 RAW（内嵌预览有颗粒）。
6. 日期水印和颗粒一起开，确认数字上没有颗粒。
7. 低速连拍和高速连拍各试一次，看等待情况。
8. 关机重开，先进一次扩展菜单，确认设置恢复，再拍一张。

| 现象 | 判断 |
| --- | --- |
| 照片没有颗粒，其他正常 | 平面映射或模式与 Z5 不同（结果码 4、5），或没走这 5 个调用点；需要读状态里的结果码（见“诊断”） |
| 照片有颗粒但出现横向条纹、错位块 | 缓存维护有问题，立即关闭并保留原片 |
| 拍摄卡死或 JPEG 损坏 | 拔卡重启恢复，记下画质和尺寸 |
