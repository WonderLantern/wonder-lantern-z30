# 对焦框颜色（`af-frame-colour`）

风格类似尼康 EXPEED 7 机型（Z9、Z8、Z6III 等）：跟踪框和人物 / 动物框平时白色，半按对上绿色、没对上红色。

2026-11-14 新增，包含在 `full` 中。v51 起照片拍摄菜单里有"对焦框颜色"一行（开启 / 关闭，默认开启，保存到 `WL-AFCOL.CFG`）。

## 效果

| 框 | 原厂 | 改后 |
| --- | --- | --- |
| 跟踪框（画面 1 大框、跟踪中）、人物 / 动物识别框，没在对焦（没半按、没 AF-ON） | 跟踪中和识别框为另一种颜色（颜色 0），画面 1 为白色 | 白色 |
| 同上，AF-S 对上 | 绿色 | 绿色（不变） |
| 跟踪框，AF-C 对上 | 和没对焦时一样（颜色 0） | 绿色 |
| 人物 / 动物识别框，AF-C 半按对上 | 颜色 0 | 绿色（v42 曾恢复原厂以避免箭头锯齿；v44 按用户要求恢复绿色） |
| 同上，没对上（AF-S / AF-C） | 红色闪烁 | 红色闪烁（不变） |
| AF-C 普通自动区域框（不跟踪、没识别到主体），对上 | 颜色 1（和 AF 点平时一样） | 绿色 |
| 录像（AF-F）人物 / 动物框、跟踪框，没半按 | 黄色（颜色 0） | 白色（v43） |
| 录像（AF-F）人物 / 动物框对上 / 没对上（不半按也一直在对焦） | 绿 / 红 | 白色（v44） |
| 录像（AF-F）跟踪框对上 / 没对上 | 绿 / 红 | 不变 |
| 其他（单点 / 动态 / 宽区域、AF-S 普通自动区域、AF-A） | — | 不变 |

## 原理

- `0x1039C930` 按"状态码 × 框种类"查 `0x107277B0` 起的样式表（29 行 × 11 列，每项 2 字节：低字节颜色代码，高字节 0 隐藏 / 1 显示 / 2 闪烁）。
- 行：每种对焦模式 5 行（`0xC237C7F9`：1 = AF-S 第 0–4 行，2 = AF-C 第 5–9 行，3 = AF-A，4 …），依次是 AF 没工作、特殊状态、AF 工作中还没结果、对上、没对上（对焦结果 `0xC25A1E70` = 2 / 1）。
- 列（`0x1039CC14`）：0–6 各种固定 AF 区域；自动区域下 7 = 普通框、8 = 识别到人物 / 动物、9 = 跟踪模式画面 1、10 = 跟踪中（由 `0xC237C815 / 0xC237C816` 判断）。
- 颜色代码 2 = 对上（对焦提示也用它判断）；4 = 没对上；3 = 画面 1 的白色大框；0、1 是原厂平时的框色。改动只把表里 21 项（v44；v43 为 17 项，v42 为 12 项，v38–v41 为 14 项）换成"白色（0x0103）"或"绿色（0x0102）"。
- AF-C 每个对焦周期之间结果会短暂变回 0（"还没结果"）。原厂 AF-C 让这一行和"对上"一行一样，避免闪；改后也这样（都为绿色）。

## 依据

- 快照 `SN000119.BIN`（研究模块 af_snap `-DSNAP_FOCUS`，单点 AF、AF-S）：`0xC181A27C` 的结构里，第 1 字节 = 对焦模式、第 2 字节 = 列、第 3 字节 = 对焦结果、第 9 字节 = 状态码（对上 3、没对上 4、没对焦 0）。
- 静态分析见 [AF 跟踪研究](af-tracking-research.md) "第 18 版"一节。

## 状态

- 构建测试：14 项改动的原值都和原厂一致，其他表项不变。
- 待实机确认：颜色代码 0 / 1 / 3 的实际颜色是按原厂用法推断的；如果改后的"白色"不是白色，告诉我实际看到的颜色。


## v43：录像模式

`AF000161.BIN`（第 21 版日志，记录了样式表的输入）：录像时对焦模式字节为 4（AF-F，第 10–14 行），不半按时状态码 10、主体框第 8 列 = 0x0100（颜色 0，黄色）；颜色 0 即原厂的黄框。半按时切到 AF-S 那一组。改为白色的是 AF-F 组第 8 / 10 列的"AF 没工作"和"还没结果"两行，以及第 9 列"还没结果"。

## v51：菜单开关

- 原厂样式表 `0x107277B0` 不再改动；改过的整张表复制一份放在固件尾部。原厂查表处 `0x1039CAEA`（`ldr r1,[pc,#0x248]` 和后面两条算下标的指令，共 10 字节）跳到 `afcol_table`：问 `afcol_choice`（先 ensure 读回 `WL-AFCOL.CFG`），开启用副本、关闭用原厂表，再执行两条被挪走的指令，并重做 `0x1039CAE4` 的 `cmp.w ip,#5`（它的标志位在 `0x1039CB04` 还要用，而函数调用会改掉标志位），回到 `0x1039CAF4`。
- 菜单：照片拍摄菜单一行（和 3D 跟踪一样，扩展根页已满），选项"开启 / 关闭"，第 0 行"开启"就是没有设置文件时的状态，所以默认开启、和以前一样。中文"对焦框颜色"，繁体"對焦框顏色"（PR 36 审查后改用补字方案：`build_cjk_glyphs.py` 把繁体字库缺的"框""顏"补进 `z30_120_extra_glyphs.json`；之前绕开缺字写成"對焦色彩"）。
- 测试：原厂表不变、副本只差计划的那些项；Unicorn 跑查表钩子：开启得到副本地址、关闭得到原厂地址，r0 / r2 / ip / lr / 栈不变，下标 r2 = 状态码 × 11、r3 = 状态码 × 3，标志位等于原来 `cmp ip,#5` 的结果，回到 `0x1039CAF4`。

## 研究（2026-11-17）：绿框的眼睛箭头为什么有锯齿

静态分析结论（尚无实机证据）：

- 链路：AF 侧 `0x1039C6B0` 填样式块 `0xC1F8F12C`，经 `0x10543CF0` 交给框模块。`0x1055F298` 用跳转表把颜色代码换成调色板序号：0→3、1→1、2→2、3→6、4→7、5→8。主体框（列 8，元素种类 3）由 `0x10595CCE` 处理：先把框记入绘制表，再算出上 / 下 / 左 / 右四个箭头的位置（坐标都取偶数），四个箭头的调色板序号都等于框的序号（箭头结构 `+0x30..+0x3C`）。`0x1055F4A6` 写箭头的开关（来自样式块 `+0x1C0`）和图片编号（`+0x40..+0x4C`，表 `0x10727DD8`；LCD 用 `0xE7 / 0xE5 / 0xE6 / 0xE4`）。
- 画箭头：`0x1054459A` → `0x10454EDE` → `0x104B86F2`：按调色板序号取颜色（YCbCr 调色板，运行时位于 `0x15C0F000`；序号 2 绿 = Y 0x95、Cb 0x2B、Cr 0x15，序号 3 黄 = Y 0xE1、Cb 0x00、Cr 0x94，序号 6 白 = Y 0xD8、0x80、0x80，全部不透明）→ `0x1047A130` 解码同一张箭头图 → `0x103BC87E` 用 CPU 写进 YUYV 4:2:2 图层：每 2 个像素共用一组 Cb/Cr（只要两个像素里有一个不透明，就整对写入框的颜色），透明度单独一层（格式 2 为 4 位、格式 3 为 8 位）。
- 所以颜色不会换图片：所有颜色用同一张箭头图，只换颜色。原厂把框和箭头的坐标都对齐到偶数像素，说明这个图层的色度是两像素一组。箭头的斜边会穿过这些两像素组。白色的色度是中性的（0x80 / 0x80），黄色主要靠亮度，看不出问题；绿色的色度偏离最大、亮度又中等，斜边上就会出现两像素一级的台阶。推测这就是锯齿的来源，需要实机特写照片确认。
- 原厂 AF-S 对上时主体框也是绿色（样式表 AF-S 状态 3 第 8 列 = 0x0102），但 AF 侧 `0x1039D760` 在状态 `+0x415` = 1 时关掉全部箭头，推测是 AF-S 锁定对焦时隐藏，所以原厂实际上看不到绿色箭头。
- 可改的地方：箭头颜色在 `0x10595E52 / 0x10595EC6 / 0x10595F38 / 0x10595FB0` 四处写入（`str r0,[r1,#0x38 / 0x3C / 0x30 / 0x34]`，r0 = 框的调色板序号）。在这里把序号 2 换成别的颜色，就只改箭头、不改框。
- 用户（2026-11-17）：原厂没对上时的红色箭头同样有锯齿。红色的色度也很极端（Cr 0xFF），这与上面的推测一致：锯齿是原厂图层两像素共用色度造成的，不是绿色特有。决定不处理，保持原厂行为。
