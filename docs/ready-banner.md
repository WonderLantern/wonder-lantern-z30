# 取景就绪提示（卡文件，2026-11-25）

卡文件加载成功后，照片实时取景画面上方会显示约 2 秒的提示，然后自动消失：

> **Wonder Lantern** 已就绪 · 16 项功能

- "Wonder Lantern"是浅青色，其余文字是白色，底是深色圆角框，左边一条青色竖条（和第 8 个标签同色）。
- 繁体："已就緒 · 16 項功能"；英文："ready · 16 features"。数字是这份卡文件包含的功能数（`full` 为 16）。
- 画在屏幕层，不会进照片和视频。
- 只在卡文件构建里有。`tools/build_card.py --no-banner` 可以去掉。

代码：`features/card/ready_banner.py`（运行时）、`features/card/ready_banner_image.py`（构建时生成图）。

## 做法

| 部分 | 做法 |
| --- | --- |
| 加载完成 | 卡文件登记一个加载完成函数 `banner_start`（常驻加载器的 INIT 段，v3 起支持）。它在原厂 IMU 任务里运行：记下"待显示"、当前毫秒时钟 `0xC18EB098`、界面语言，然后返回 1。不画任何东西。 |
| 语言 | 加载完成时读一次属性 `0x1400`（`0x10465984`），存成 0/1/2（英/简/繁）。绘制时不调用属性服务，因为它走原厂属性服务 `0x101993DE`，不适合在图形任务里调用。这是在"只置标志和时间"之外多做的一件事。 |
| 绘制 | 挂在原厂图像绘制包装函数里调用渲染器的地方 `0x103BC4D0`（`bl 0x10477C9C`），和电量百分比同一处。先让原厂图像照常画完，再按条件用同一个渲染器画我们的图。 |
| 条件 | 绘制目标是屏幕层（`0xC1808758` = 2）、照片取景（`0xC18292AC` = 0）、界面阶段 1 或 2、没有设置页盖在取景上（`0xC2016904`、`0xC20168F8` 都为 0）。和竖拍显示在实机上用的条件相同。 |
| 图 | 构建时用相机自己的字库（原厂 CJK 字体轮廓加扩展字）在 PC 上画出来：纯 Python 的扫描线填充，非零环绕，每像素 4×4 采样，不依赖图像库。三种语言各一张，宽度统一为 480（16 的倍数），高 48。每像素 4 字节，非预乘的 RGBA（OpenVG `VG_sABGR_8888`，渲染器的 0 类），三张共 270 KB，在卡文件的 tail 里（加载后在 RAM）。 |
| 描述符 | 照抄原厂取景图标的字段布局（QEMU 里用 `tools/probe_image_descriptors_qemu.py` 读出来）：`+0` 类型 1，`+4` 类别 0，`+8` 像素，`+0x10` 源框 (0,0,w,h)，`+0x18` 屏幕框 (x0,y0,x1,y1)，`+0x20` 不透明度 255，`+0x40` 角度 360，`+0x4C`/`+0x50` 缓冲宽高（16、8 的倍数）。每行字节数由渲染器算：宽度补到 16 的倍数，乘以表 `0x1069FECC` 里该类别的字节数（0 类为 4）。`+0x2C` 保持 0：非 0 会改走 SRC 混合，并清掉框外的四条带。 |
| 位置 | 水平居中，上边在 y = 64（顶栏图标下面）。 |
| 时长 | 加载后第一次在照片取景里有图标重绘时开始计时，显示 2 秒，没有时间限制。 |
| 擦除 | 时间到后的下一次绘制：把混合模式设成 `VG_BLEND_SRC`（`vgSeti(0x1104, 0x2000)`），用原厂矩形入口画颜色 0 的矩形盖住整个框，再恢复原来的混合模式。和竖拍直方图 v25 在实机上验证过的擦法一样（从钩子里调用原厂清除没有效果）。显示中离开取景，就等回到取景后再擦。 |
| 状态 | tail 里 16 字节：阶段（1 待显示、2 显示中、3 待擦除、4 结束）、开始时间、语言。 |
| 冲突 | 和电量百分比（实验功能，不在 `full` 里）挂同一处，同时选会拒绝构建。 |

取景时原厂渲染器一秒有两三批调用（QEMU 里每 0.5 秒一批，每批 8 次），所以提示在进入取景后半秒内出现，到时后半秒内消失，不需要强制重绘。竖拍显示 v3 的强制全部重绘在实机上冻住过信息层，这里没有用。

## 验证

- 单元测试 `tests/test_ready_banner.py`：三种语言的图同宽、16×8 对齐、圆角处透明、中间不透明；描述符字段；只有卡文件构建（和 QEMU 测试构建）才有；与电量百分比冲突时拒绝构建。
- QEMU（`tools/verify_ready_banner_qemu.py`，`full` 的 QEMU 测试构建，简体）：
  - 原厂照片取景，写入改动后手动调用 `banner_start`，不强制刷新；
  - 0.5 秒时已显示，1.5 秒时仍在，2.5 秒时阶段为"结束"，框内像素与原厂画面一致；
  - 截图在 `build/ui-qemu/ready-banner-hans/`。
  - QEMU 测试构建是闪存构建，tail 在闪存里：状态字放在 RAM（原厂菜单记录 0 没用的 16 字节），像素由工具复制到原厂堆里。渲染器不接受闪存里的像素（第一次运行时什么也没画）；卡文件里 tail 本来就在 RAM，不受影响。
- 实机（2026-11-25，常驻 `0x67f308e7`）：
  - 相机的取景画面在没有变化时**不重画图标**（QEMU 的测试画面一直在动，所以 QEMU 里看不出来）。开机后不操作就不会出现；半按快门或按 OK 引起重绘后才出现。
  - 诊断版（`--banner-debug`，状态页"版本"一行显示读数）：`P4 C0350 DD4`，即走完全程、钩子调用 848 次、画了 212 次，提示能正常显示。
  - 第一版普通卡还有"加载后 30 秒内没进照片取景就不显示"的限制：第一次半按如果晚于开机 30 秒，提示就被跳过。已去掉这个限制。
  - 诊断版提示到时会自己消失；能否出现要看加载完成时相机是否还在重绘图标（开机后几秒内往往还在）。

## 图像要对齐（2026-11-25，实机确认）

几版卡文件里提示的绘制次数（诊断读数 D）都有两百次左右，但只有一版在屏幕上看得到。画提示用到的描述符、像素、代码都一样，唯一不同的是像素数据的地址：看得到的那版碰巧在 128 字节边界上，看不到的几版在 64 字节边界之外 8、28、40 字节处。相机的图形处理器不接受没对齐的图像数据（QEMU 不检查，所以 QEMU 里一直正常）。

现在三张图都放在 256 字节边界上（`PIXEL_ALIGN`）。加载器总是把 tail 放在 64 KB 边界上（`features/card/loader.py`：`(块地址 + 0x10007) & ~0xFFFF`），所以 tail 里的偏移对齐即可。`tests/test_ready_banner.py` 检查三个链接基址下都对齐。

实机（`output/card-banner-v1-repaint5`，对齐后）：不碰按键，提示自己出现、自己消失；半按后信息层照常更新。读数 `P4M0W07K1AD52R00U0X0`：画了 82 次，下面的重绘触发一次也没标记（`M0`），出现靠的是加载完成后相机自己的几次重画。之前"要半按才出现""半按也不出现"，主要是没对齐造成的。

## 重绘触发（已关闭）

下面的做法试过三版，实机上都没有起作用，现在由 `ready_banner.REPAINT_TRIGGER = False` 关闭，代码保留：
- 第一版挂在竖拍显示的界面 update 事件上：空闲的取景画面里这个事件不运行。
- 第二版放宽了判断条件：结果相同，读数显示触发运行时提示根本不在"待显示"状态。
- 第三版挂在原厂取景信息刷新入口 `0x1032427E`：空闲时它也几乎不运行（26 次），提示已经靠原厂重画出现了。

关闭后不再改竖拍显示的两处钩子，也不再挂 `0x1032427E`。

### 当时的设计（2026-11-25）

为了不按键也能出现，提示在该出现、该消失时各让原厂重画一次取景图标。没有用整页重绘请求：竖拍显示 v3 的 `10453FAC(…, 0x1F, 7)` 冻住过信息层，v13 的"立即重画"让相机卡死过。用的是竖拍显示 v15–v19 在实机上验证过的做法：给原厂刚画过的控件置脏标志 `+0x44`，由原厂自己的遍历（约每秒 3 次）去画。

| 部分 | 做法 |
| --- | --- |
| 记录 | 竖拍显示在遍历调用控件绘制处（`0x102BD3F0`）的钩子里，不论竖拍开关，都调用提示的 `record`：取景容器 `0xC2017AB8` 里有绘制函数、且不是只清背景（`0x104B45DB`）的控件，记下最近的 8 个（去重）。只清背景的控件不记：竖拍 v16–v18 里标记它们会把图标擦掉。 |
| 触发 | 竖拍显示的界面 update 事件钩子（`0x10310C08`，界面任务，约每秒 5 次）里调用提示的 `tick`：待显示时标记一次；显示满 2 秒后再标记一次（让擦除尽快执行）。只在照片取景、照片后端、没有设置页时标记；记录为空时等下一次。 |
| 依赖 | 只在含竖拍显示（`portrait-ui`，`full` 里有）的卡文件构建里有；没有它时提示照旧靠原厂自己的重绘。闪存构建不变。 |
| 状态 | 状态块扩为 64 字节：`+24` 已标记（1 出现、2 擦除），`+28` 记录过的控件数，`+32` 起 8 个控件。诊断读数加 `M`（已标记）和 `W`（记录数），去掉了空格。 |

Unicorn（`tests/test_card_loader.py`）：用真实常驻加载器加载卡文件后，对假控件执行 `record` 和 `tick`：只清背景的控件、其他容器、重复的都不记；只保留最近 8 个；有设置页时不标记；标记一次后不再标记；显示 2 秒后做擦除标记。QEMU 里取景测试画面一直在动，看不出触发的效果，所以没有 QEMU 截图，要实机看。
