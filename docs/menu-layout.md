# 自定义菜单的入口布局与状态页：设计方案（2026-11-25）

> 状态：第 1 步（分类页）2026-11-25 实机正常，说明见 [menu-framework.md](menu-framework.md#根页分类2026-11-25)；第 2 步（状态页）已实现、QEMU 通过，还没上机，见 [menu-framework.md](menu-framework.md#状态页2026-11-25)，下文的"常驻固件"一行实际叫"加载器"（原因见该节）。直达行收缩、标签默认打开还没做。

## 现在的问题

`full` 构建里，扩展功能的入口分散在三处：

| 位置 | 现在有的行 |
| --- | --- |
| 设定菜单"自定义菜单"一行，或第 8 个标签（`menu_tab`） | 根页 8 行：画幅、高光显示、竖拍、日期水印、NEF、码率、Gyro、快门声音 |
| 照片拍摄菜单末尾的直达行 | 6 行：画幅、高光显示、竖拍、日期水印、3D 跟踪、对焦框颜色（原厂 34 行变 40 行） |
| 视频拍摄菜单末尾的直达行 | 1 行：码率 |

- 根页是平铺列表，已经占满一屏的 8 行（`MAX_ROWS`），再加功能就放不下。
- 3D 跟踪和对焦框颜色因为根页满了，只能从照片菜单进去，在扩展菜单里找不到。
- 照片菜单被加了 6 行，原厂设置和我们的混在一起，要往下翻很久。
- 没有一处能看出卡文件是否正常加载、当前是哪个版本、设置有没有存上。

## 目标

1. **一个家**：所有功能都能从扩展菜单进入；拍摄菜单只留最常用的 1～2 个直达行。
2. **分类**：根页不再平铺功能，而是"状态 + 几个分类"，以后加功能只往分类里加。
3. **状态页**：一眼看到加载情况、版本、设置是否保存，以及几项会影响成片的当前值。
4. 不改常驻 EG（只换卡文件）；固件版本页照常能打开、能升级。

## 新布局

```
第 8 个标签（或 设定 → 自定义菜单）
└─ 根页
   ├─ 状态 ............ 正常          → 状态页
   ├─ 拍照                            → 画幅 / 高光显示 / 日期水印 / NEF 压缩
   ├─ 对焦与显示                      → 3D 跟踪 / 对焦框颜色 / 竖拍显示
   ├─ 视频                            → 视频码率 / Gyro 电子减震
   ├─ 声音                            → 现有的声音分组页（开关、选择声音）
   └─ 实验（只在研究构建里出现）       → 模块宿主 / 研究页
```

`full` 根页 5 行，留 3 行给以后的分类。各分类页最多 4 行，也都有余量。

### 规则

| 规则 | 说明 |
| --- | --- |
| 分类表 | `menu_framework.py` 里一张 `CATEGORIES` 表：`(键, 标题, 成员)`，替代现在的 `ROOT_ORDER`。根页顺序、分类页内容、控件 ID 都从这张表推出 |
| 空分类不显示 | 构建里一个成员都没有的分类不出现在根页 |
| 单成员分类展开 | 只有一个成员时（比如只选了 `photo-zebra`），根页直接放这个功能，不多走一层 |
| 分类行的值列 | 没有值列，标签占满整行，避免根页又变杂 |
| 状态行的值列 | 显示 `正常` 或 `需检查`，这是根页唯一的值 |
| 功能页的父页 | 打开功能页时把父页写成所在分类页，返回键就回分类页。`page_return` 本来就是按父页的页号返回（`ldrh [parent,#2]`），不用改 |
| 声音 | 现有的声音分组页（`SOUND_GROUP_INDEX`）原样作为"声音"分类，不重做 |

分类页本身就是现在声音分组页的推广：一个 44 字节的页面对象放在状态块里，行数 = 成员数，每行的值列显示该功能的当前值（复用各功能已有的 `value_slot`，就是现在根页右侧显示的那个值）。这样分类页看起来和原厂拍摄菜单一样："名称 …… 当前值"。

### 直达行收缩

照片菜单只留**画幅**，视频菜单只留**码率**。其余 5 个直达行去掉，改从扩展菜单进入。

- 新构建选项 `direct_rows`，默认 `('aspect', 'bitrate')`；GUI 和 `tools/build_card.py --direct-rows` 可以改，想保留旧习惯的人可以全选。
- 照片菜单从 40 行回到 35 行。
- 直达行目前是构建时定的（改的是页面描述的行数），所以不做"在相机里开关直达行"，避免运行中改行数。

### 入口

第 8 个标签是主入口；`menu_tab` 关闭时仍用设定菜单的"自定义菜单"一行。第 8 个标签第三版（右键改走框架 `open`、青色色条）实机确认后，再把 `menu_tab` 改为默认打开。

## 状态页

根页第一行进入。最多 8 行，前 4 行是系统信息，后 4 行是会影响成片的当前值：

```
状态
  卡文件          已加载 S=01
  版本            v3 11-25 7c27163
  常驻固件        f7e0eb07
  设置            已保存
  照片画幅        3:2
  NEF 压缩        无损
  日期水印        关
  视频码率        高
```

| 行 | 来源 | 按确定 |
| --- | --- | --- |
| 卡文件 | 加载器状态字 `0xC1832D30`（菜单记录 0 的 `+0x0C`）。闪存构建显示"固件内置" | 无动作 |
| 版本 | 构建时写入卡文件的一段固定文字：卡文件格式版本、构建日期、git 短哈希 | 无动作 |
| 常驻固件 | 卡文件头里的常驻 id（取前 8 位十六进制），构建时写成固定文字 | 无动作 |
| 设置 | 框架已有的保存结果（失败时弹"设置未保存"的那个状态）：`已保存` / `未保存` | 无动作 |
| 后 4 行 | 对应功能页的 `value_slot` | 打开该功能页（返回回到状态页） |

说明：
- 能看到扩展菜单，卡文件就一定加载了，所以"卡文件"一行实际只会出现 `S=01` 或 `S=0E`（加载完成函数没有返回 1，改动已写入）。`S=0E` 和"设置未保存"时，根页状态行显示 `需检查`。其他失败代码仍只能看 `Z30/WL.LOG`。
- 后 4 行默认是画幅、NEF 压缩、日期水印、视频码率，因为它们会改变拍出的文件；构建里没有的功能不显示，行数随之减少。列表可以用构建选项 `status_rows` 调整。
- 状态页不新增常驻能力：状态字已在 RAM 里，版本和常驻 id 是构建时的字符串，不需要重刷 EG。

## 文字

新增的文字（简体 / 繁体）：

| 英文 | 简体 | 繁体 |
| --- | --- | --- |
| Status | 状态 | 狀態 |
| Photo | 拍照 | 拍照 |
| Focus & display | 对焦与显示 | 對焦與顯示 |
| Video | 视频 | 影片 |
| Sound | 声音 | 聲音 |
| Experimental | 实验 | 實驗 |
| Card file | 卡文件 | 卡檔案 |
| Version | 版本 | 版本 |
| Resident firmware | 常驻固件 | 常駐韌體 |
| Settings | 设置 | 設定 |
| Saved / Not saved | 已保存 / 未保存 | 已儲存 / 未儲存 |
| Loaded / Built in | 已加载 / 固件内置 | 已載入 / 韌體內建 |
| OK / Check | 正常 / 需检查 | 正常 / 需檢查 |

`TextResources.alloc` 构建时会检查字形。缺字时**换词**，不为几个字重刷常驻 EG。分类页内的功能名去掉重复的前缀（"拍照"分类里叫"画幅"而不是"照片画幅"）；直达行和状态页仍用完整名称。

## 页号与状态块

- 分类页：拍照 970、对焦与显示 971、视频 972、实验 973（961～969 已被各功能页占用，962 是声音分组页）。
- 状态页：一个页号，接在分类页后面。

## 实施步骤

1. **分类页**：`CATEGORIES` 表、分类页注册和渲染、功能页父页改为分类页、单成员展开。`full` 的字节会变，这是预期的。
2. **状态页**：版本字符串和常驻 id 在构建时生成；渲染时读状态字和保存结果；后 4 行复用各页的值并能跳转。
3. **直达行收缩**：`direct_rows` 选项、GUI 和 `build_card.py` 参数；更新 `verify_native_rows_qemu.py`。
4. **第 8 个标签默认打开**：等第三版实机确认后单独提交。

## 验证

- 单元测试（`tests/test_menu_framework.py`）：
  - 分类顺序、空分类隐藏、单成员展开；
  - 每页不超过 `MAX_ROWS`；
  - 功能页父页是所在分类页；
  - 状态页行数随构建变化，`direct_rows` 默认只有画幅和码率。
- QEMU：
  - 标签 → 根页 → 分类 → 功能页 → 选值 → 返回分类页 → 返回根页 → 返回标签栏，每一层焦点都在第一行；
  - 状态页各行文字（简体、繁体、英文）；从状态页跳到功能页再返回；
  - 照片菜单 35 行、视频菜单 27 行，直达行仍正常；
  - 固件版本页能打开。
- 实机：一份完整预设的卡文件（`full` 加 `menu_tab`），按上面的路径走一遍，再拔卡重启确认恢复原厂、固件版本页正常。

## 取舍

- **多一层**：从标签到选项要按 3 次（根页 → 分类 → 功能页），比现在多 1 次。换来根页只有 5 行、以后加功能不用挤。最常用的画幅和码率仍有拍摄菜单直达行。
- **不做滚动的平铺列表**：原厂长列表可以滚动，但我们的页目前按一屏 8 行做，滚动和分组标题都还没研究，风险比分类页大。
- **不做运行中开关直达行**：要在运行中改页面描述的行数，留到以后需要时再研究。
