# Z7 II JPEG 预拍摄实现对照（2026-11-21）

来源：`github.com/JKWTCN/z7ii-extensions`（MIT，提交 `9ddc447`，2026-11-21），
`plugins/pre_capture/*`、`docs/jpeg-pre-capture.md`。注意不是 `z72-custom-firmware`
（那个仓库只有水平仪/九宫格/5GHz，没有预拍摄）。作者称 Z7 II C1.70 真机可用：
一组 77 张，其中 4 张预拍。本文只记录对照阅读结论，Z30 侧地址除特别注明外都是待验证线索。

## 他们的整体路线

1. **不是逐张单拍，而是让原生 H\*（高速连拍延长）静音连拍一直跑**。前置条件由
   `capture_warning()` 检查：单一存储卡、静音属性 `0x057a==1`、释放模式 `0x8019`（H\*）。
   菜单不替用户改设置。
2. **独立轮询任务**：`0x103d3dff(0x10005)` 取一个原生任务描述符（28 字节）复制后改
   stack=16384，用 `0x103dc46b(task_control, worker, desc)` 创建，`0x103606df` 启动。
   worker 只是 `for(;;){ worker_step(); delay(50); }`，**不等待 event**。
3. **启动连拍**：调用 SDK 拍摄入口（Z7 II `0x103ba6ea`），请求 5 个 word：
   `{0x200 卡/0x10200 RAM, 0, continuous=1, 0, count=8}`。注释：`+8` 置 1 使采集越过原生初始配额持续运行。
   返回 `0x1d` 时特殊处理（恢复目的地）。停止用紧随其后的 `0x103bac41(&mode=0)`。
4. **AF 准入绕过**：把 SDK 入口整段（0x556 字节，FNV 校验 `0x084406f6`）复制进模块 RAM，
   重定位 83 个 BL，只把 +0xd6 处 AF 输入掩码查询 `0x1022bbd5` 换成本地函数：
   当本模块持有半按/AF-ON 时返回 0。原因：按住半按时原生 SDK 会因 AF 活动拒绝新拍摄。
5. **在原生存卡任务里截流**：替换 card/file/peer 分发 slot。触发前的帧：
   - 用原生 JPEG 段接口逐段复制到自有 pool 租约（pool `0xf`，查询 `0x10298d15`，
     申请 `0x10298beb`，归还 `0x10298c61`），环形最多 12 槽 / 128 MiB，按时间窗 0.3–1.0 s 过期；
   - 回复原生"已处理"，不写卡；对未打开的 DCF ID 原生回滚 `0x105070fd`。
   全按 = 置 FROZEN，窗内缓存帧由 worker 自己创建 DCF 文件写出（`pre_capture_store.h`，
   含 EXIF 时间排序），之后的帧走原生写卡，保持全按即同一次 H\* 连拍继续。
6. **事件计数**：SDK 输入监听 `0x04100074`（累计张数）/`0x04100075`（结束），转发原生不吞事件；
   结束后要求所有 writer/ACK/租约归零才允许下一轮，20 s 超时则禁用功能而不是强行释放。
7. Z7 II 双 EXPEED，有 peer（从处理器）写卡路径；Z30 单处理器，这部分大概率不需要。

## 与 Z30 已知地址的对应（已粗查）

| 项 | Z7 II C1.70 | Z30 | 状态 |
| --- | --- | --- | --- |
| SDK 拍摄入口 | `0x103ba6ea`，长 0x556 | `0x1020A630`，至 `0x1020ABCA` 约 0x59a，源字符串 `CaptureCameraControl.c` | 返回码 0x1d/0x20/0xd/0xe 同族，请求按 byte0..3、+4、+8、+0xc 读取，形状一致；字段语义待核 |
| 停止 | `0x103bac41(&mode)`，紧随入口 | `0x1020ABCA(r0=ptr)`，紧随入口，读 [r0] 8 字节，调用 `0x1020a02a` | 候选，未验证 |
| 静音属性 | `0x057a` | `0x57B` | 已确认（Z30） |
| JPEG pool | pool `0xf` | selector1 → pool15 | 一致 |
| JPEG 段接口 | `0x104ef019` 段数 / `0x104eefc5` 取段 | `0x102B6FBE` / `0x102B688E` | 对应 |
| 完成/计数事件 | `0x04100074/75` | 已见 `0x04100046` | 需找 Z30 的连拍计数/结束事件 |

## 对 Z30 v4 的直接启示

- v4 真机卡在"投递返回 0 但 worker 不跑"。Z7 II 完全不用 event 投递：克隆原生描述符建任务 + 50 ms 轮询。
  建议 v5 先换成这种任务模型，只验证 worker 心跳计数写进 DBG。
- v4 用单拍请求（只设 +0x10=1）并让用户只开静音。Z7 II 路线要求用户选 H\* 并用 `+8=1` 连拍；
  半按期间拍不到可能也与 AF 准入拒绝有关，可先只记录入口返回码确认。
- 预帧不写卡的方式是"在存卡任务里回复已处理 + 回滚 DCF ID"，而不是改保存 hook 返回值；
  这比我们现有 `0x1009F9B8/0x1009FC28` 保存 hook 的思路更完整，值得照着找 Z30 的存卡 task slot。
