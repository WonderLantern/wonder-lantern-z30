# SD 卡功能加载（实验）

功能代码和补丁放在卡上的 `Z30/WL.PATCH`。固件里只常驻带常用字的 CJK 字体和一个加载器。没有卡或文件时，相机就是原厂行为（多出的字体不影响原厂界面）；出问题拔卡重启即可恢复。前期探测见 [card-loader-probe.md](card-loader-probe.md)。

状态：**2026-11-24 实机通过**（`output/card-v2`，`full`，常驻 id `0xda3b9dbc`）：
- 放入卡文件后各项功能正常；
- 拔卡重启恢复原厂；
- 损坏的卡文件（`output/card-v2-damaged`，在偏移 `0xF858` 翻转一个字节）：`WL.LOG` 为 `WL.PATCH S=07 B=00000000 T=00000000 E=00000000`，相机保持原厂；
- 加载卡功能后，从固件版本页升级不受影响；
- 正常加载的 `WL.LOG`：`WL.PATCH S=01 B=C2C70000 T=0001CDE0 E=00000078`。tail 放在内存池的 `0xC2C70000`（RAM），118240 字节；写入 120 条 edits，与构建报告一致。

## 组成

| 部分 | 内容 |
| --- | --- |
| 常驻 EG | 原厂；扩展的 CJK 字体（开机就读，必须常驻，带常用字集，见下文）；加载器；IMU 任务触发点 `0x1021C360`（原厂调用和分支保持不变） |
| `Z30/WL.PATCH` | 所选 preset 的 tail（在 `0x20000000` 链接）、tail 重定位表、全部 edits（运行时地址、预期字节、新字节、各自的重定位） |

- 卡文件头带有常驻 id，只能配同一次构建出的常驻 EG 使用。
- 改功能代码只需换卡文件。加载器或字体变了才需要重刷 EG。

## 常驻字体与常用字集

为了加字时不用重刷，常驻 EG 的字体 2（简体）补全 GB2312 一级字（3755 个），字体 0（繁体）补全 Big5 常用字（5401 个）。原厂各只有约 720 个汉字。

- 新补字形：简体 3064 个，繁体 4705 个，平均约 350 字节。扩展后字体 2 约 1.31 MB，字体 0 约 2.15 MB。常驻 EG 约 37.4 MB，低于 EG bank 的 `0x2940000`。
- 区间内的偏移是 16 位，所以新字形按 64 KiB 分成多个索引区间（`platform/fonts.py` `extend_font`）。
- 普通整包构建仍然只补标签用到的字，产物与以前逐字节相同；只有 `card.build_resident` 用 `common=True`。
- 字形由 `tools/build_cjk_glyphs.py` 从 Noto Sans CJK 生成，存在 `platform/z30_120_extra_glyphs.json`。
- 新标签只要用的是常用字集里的字，字形表就不变，常驻 EG 也不变，只需换卡文件。用到集外生僻字时字形表会变；`build_card.py --patch-only` 会发现常驻 id 变了并报错，提示需要重刷。

## 构建

```powershell
python tools/build_card.py --source Z_30_0120.bin --output output/card
```

用 `--preset` 选功能，例如 `--preset focal-length battery-percent`。只更新卡文件时加 `--patch-only`，并指向放着已刷 EG 报告（`EG209020.json`）的同一个输出目录；常驻 id 不一致时会拒绝生成。

## 加载过程

1. IMU 任务约每 50 ms 一个 tick。开机约 3 秒后开始尝试打开 `A:\Z30\WL.PATCH`，每 0.5 秒一次，约 30 秒后放弃。
2. 找到文件后：
   - 读头部，检查魔数、格式、常驻 id 和大小；
   - 从原厂内存池申请"文件大小 + 64 KiB"，把文件主体读到 64 KiB 对齐的位置，确认读到文件末尾，然后关闭文件；
   - 检查 CRC32、重定位范围，以及每条 edit 的目标范围和预期字节。
3. 全部通过后：
   - 重定位 tail，对它做双核缓存同步；
   - 逐条重定位并写入 edits。代码区经 DRAM 别名 `+0xBC400000` 写入，scatter 区直接写 RAM；每条代码 edit 都同步缓存。
4. 写入之前任何一步失败，都会释放内存，不做任何改动。

## 卡文件构建时如何处理不可写区

EG 的 `0x10700000` 之后不可写，三处改动改成"RAM 副本 + 改指针"。这些处理只在卡构建里生效，普通整包构建保持字节不变：

- **菜单回调记录**（声音入口、照片菜单、视频菜单）：复制 5 个字，改菜单对象 `+16` 处的指针（对象在 scatter RAM 里）。
- **码率表** `0x10713154`：放一份改好的副本，改可写区里的字面量 `0x10355798`。
- **Wi‑Fi 国家表** `0x114A37BC`：放一份改好的副本，改字面量 `0x101F51EC`。

## 状态与日志

只要找到了文件，就会写 `Z30/WL.LOG`，内容一行，形如 `WL.PATCH S=01 B=D0010000 T=0001CDE0 E=00000078`：

- **S**：结果代码，含义见下表；
- **B**：tail 的基址；
- **T**：tail 大小；
- **E**：edits 条数。

| S | 含义 |
| --- | --- |
| 01 | 加载成功 |
| 03 | 读文件失败 |
| 04 | 文件格式或大小不对 |
| 05 | 卡文件不是给这个常驻固件构建的 |
| 06 | 内存不足 |
| 07 | CRC 不对（文件损坏） |
| 08 | 结构错误 |
| 09 | 相机内存与补丁预期不符（没有写入） |
| 0A | 关闭文件失败 |
| 0B | 缓存同步失败（没有写入） |
| 0C | 写入后有代码区缓存同步失败，需重启 |

没有文件就不写日志。RAM 状态字是 `0xC1832D30`（菜单记录 0 的 `+0x0C`）。

## 实机检查

只换卡文件时，出问题拔卡或换文件即可恢复，不需要检查固件升级。刷新的常驻 EG 时仍要做第 1 步：没有卡时相机启动的就是它，只能通过固件版本页把它换掉。

1. 刷常驻 EG，**不放卡文件**：确认 Setup → Firmware version 能正常进入、升级流程正常；菜单、拍照、录像和原厂一致；卡上没有 `WL.LOG`。
2. 放入 `Z30/WL.PATCH` 并重启：约 3 秒后功能应出现；`WL.LOG` 显示 `S=01`。逐项试用：扩展菜单、声音、画幅、同屏、码率、斑马纹、日期戳、竖拍 UI、陀螺仪、3D 跟踪、对焦框颜色、焦距显示、Wi‑Fi、NEF 菜单、MTP。
3. 加载后再确认 Setup → Firmware version 正常。
4. 放一个损坏的文件（改一个字节）：`WL.LOG` 显示 `S=07`，相机保持原厂。
5. 拔卡重启：恢复原厂。

## 已知风险

- 修改代码时另一个核可能恰好在执行被改的函数。加载放在开机约 3 秒、通常空闲的时候，但无法完全排除。
- 只在 IMU 任务运行时才会加载。如果某些开机模式下 IMU 任务不运行，功能就不会出现，日志也不会写。
- 菜单之类的数据如果在加载前已被原厂缓存，改动可能要重新进入页面才生效。
- 开机约 3 秒内功能不可用。
