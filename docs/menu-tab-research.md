# 左侧菜单栏新增标签：研究记录（2026-11-24）

> 正式版已完成，说明见 [menu-framework.md](menu-framework.md#菜单左侧第-8-个标签构建选项-menu_tab2026-11-24)。下面是研究过程，保留备查；"图标"和"根页的返回箭头"两处结论已被正式版取代。

目标：在菜单左侧标签栏（播放、照片拍摄、视频拍摄、自定义设定、设定、润饰、我的菜单）加第 8 个标签，作为扩展功能的独立入口。本轮只做静态分析和 QEMU 观察，没有改固件产物。

## 标签栏的结构（静态分析，Z30 C 1.20）

- 标签栏本身是一个原厂页面：页号 1，页面对象 `0xC1832D50`，其他菜单页（包括我们的扩展页）的父对象都是它。
- 页面描述在 RAM `0xC1872230`（scatter）：
  - 标志 `0x1000`；
  - 几何 `0x11471374`、布局 `0x112FF204`、控件表 `0x113000C4`、事件分派 `0x113057E4`；
  - 行数 `0x70007`：共 7 行，每屏 7 行。
  - **7 个标签就是这 7 个控件**，所以标签栏是表驱动的。
- 控件（每个 28 字节）：
  - +0 图标编号：`0x11F`、`0x3F1`、`0x3F2`、`0x1B6`、`0x241`、`0x290`、`0x29B`；
  - +4/+8 备用图标：只有润饰（`0x446`）和我的菜单（`0x449`）有；
  - +16 标志 2；+20 序号 0～6；+24 控件 ID `0x14C3`～`0x14C9`。
- 几何：7 个 64×60 的格子，从 y = 0 排到 420。屏幕高 480，下面 420～480 是"?"帮助图标的位置。
- 事件分派：每个标签一张事件表，其中 `0x256` 事件的目标就是右侧菜单的页号（播放 `0x12`，照片拍摄 `0x27`……）。
- "标签 → 页号"表在 ROM `0x1074BFAC`：`0x12, 0x27, 0xCA, 0x118, 0x18D, 0x285, 0x351, 0`，由可写区的字面量 `0x10428A40` 引用（函数 `0x10428968`）。

## 上次停留的标签（QEMU 观察 + 静态分析）

工具：`tools/probe_menu_tabs_qemu.py`，结果在 `build/ui-qemu/menu-tabs`。

- 切换标签时**不写**任何设置。
- 退出菜单（事件 `0x24E`）时，`0x10428968` 一带的代码写入一串设置：
  - `0x3D07` = 标签栏当前行（首行 +24 加光标 +22），就是上次停留的标签；
  - `0x3D00`～`0x3D06` = 各菜单页自己的位置。
- 再次打开菜单时，`0x10428A64` 读取 `0x3D07`，按"每屏行数"拆成首行和光标写回标签栏，再用光标查上面的页号表。**没有范围检查。**
- 风险：如果在新标签（第 8 个，值 7）上退出菜单，`0x3D07 = 7` 会被存起来。以后在没有卡、或卡文件没加载时打开菜单，原厂会按每屏 7 行算出首行 = 7。标签栏只有 7 行，这个状态不合法，很可能画面错乱或卡死，而这时连固件版本页都可能进不去。

## 可行性

可以做，所有要改的地方要么在 RAM 里，要么在可写的代码区，都能放进卡文件：

| 项 | 做法 |
| --- | --- |
| 第 8 个标签 | 复制控件表（加 1 个控件）、事件分派表（加 1 张事件表，`0x256` 指向扩展根页 955）、几何表；把 RAM 里的页面描述改成 8 行 |
| 页号表 | 复制一份加入 955，改字面量 `0x10428A40` |
| 上次停留的标签 | 卡文件在写入 `0x3D07` 的地方（`0x1042898A` 一带，DRAM 区）挂钩：值 ≥ 7 时改写成设定标签（4）。这样存下来的值永远在原厂范围内；拔卡后原厂也不会读到 7 |
| 图标 | 先借用一个原厂图标做原型；自绘图标要先研究图像资源的格式 |

**还没解决的问题**（需要 QEMU 原型验证）：
1. **高度**：8 × 60 = 480，会压住"?"帮助图标。可以把每格改成 52 像素（8 × 52 = 416），但原厂图标的位图可能是按 60 高设计的，要看实际效果。
2. **写死 7 的代码**：上下键循环、高亮、帮助等地方可能按 7 个标签处理，需要在 QEMU 里逐项试。
3. **断电**：在新标签上直接关机时，原厂是否也走同一段写入代码。挂钩放在写入函数里能覆盖所有调用路径，但需要验证。
4. **卡加载前**：开机约 3 秒内菜单里没有新标签；加载器运行时如果菜单正开着，标签栏的行数会在运行中改变，需要确认不会画乱（或者在菜单打开时推迟修改）。

## QEMU 原型（2026-11-24）

实现：`features/menu_tab.py`，研究选项 `build(..., menu_tab=True)`，默认关闭，普通构建字节不变。改动如下：
- 标签栏页面描述改为 8 行，换成新的几何表（每格 64×52）、控件表（第 8 个控件，ID `0x14CF`）和事件分派表（第 8 张事件表复制自设定标签，`0x256` 指向扩展根页 955）；
- "标签 → 页号"表加入 955，改字面量 `0x10428A40`；
- 写入 `0x3D07` 的指令（`0x1042898A`）挂钩：值 ≥ 7 时写 4；
- 框架的 `getter` 在根页被直接查询且状态块还不存在时，先调用 `ensure`。

`tools/probe_menu_tabs_qemu.py --image build/menu-nosound/tab.bin --report …`（`full` 加 `menu_tab`），英文和简体：

| 检查 | 结果 |
| --- | --- |
| 绘制 | 8 个标签，每格 52 像素排列整齐；第 8 个选中时像原厂标签一样黄色高亮，右侧显示扩展根页，标签栏保持可见 |
| 触摸第 8 个标签 | 右侧子页面就是扩展根页，状态块在查询时建立 |
| 根页 → 功能页 → 返回 | 触摸两次打开画幅页（第一次把焦点移进列表），按一次返回回到根页 |
| 上下键 | 第 7 个往下到第 8 个；第 8 个往下循环到第 1 个；往上正常 |
| 停在第 8 个标签退出菜单 | 写入 `0x3D07 = 4`，由挂钩写入，没有存下 7 |
| 原厂 7 个标签 | 触摸切换都正常，各自的子页面不变 |

截图：`build/ui-qemu/menu-tab-proto*`。其中一次运行在按键时卡住，日志里没有异常，重跑后正常，按 QEMU 偶发问题处理。

与预期不同的地方：
- **图标**：第 8 个标签显示的是"列表加时钟"图标（原厂"最近的设定"），而不是控件里填的铅笔图标 `0x1B6`。说明标签图标按序号从原厂的图标表里取，而这张表里恰好有第 8 个。要换成自己的图标，需要找到这张图标表和位图格式。
- **根页的返回箭头**：扩展根页用的是子页面版式，右上角有返回箭头。作为顶层标签页，应该换成和原厂设定菜单一样没有返回箭头的版式。

还没验证：
- 在第 8 个标签上直接关机时，原厂是否也经过同一段写入代码（挂钩放在写入函数里，理论上覆盖所有路径）；
- 卡文件方式下，加载器在菜单打开时修改标签栏的情况；
- 实机效果。

## 建议

1. 做一个只在 QEMU 里用的原型：借用原厂图标、每格 52 像素，验证绘制、触摸、上下键、进出扩展页、退出菜单时写入的 `0x3D07`。
2. 原型可行后再做正式版：图标、卡文件实现，以及专门的测试："停在新标签时退出或关机 → 拔卡开机 → 打开菜单"必须正常。
3. 如果写死 7 的地方太多，就退回设定菜单里"扩展功能"入口加分类页的方案。

## 正式版补充（2026-11-24）

- **图标链路**：控件 `+20` → 图标组表 `0x10734DB4`（每组 6 个图像 ID：选中、不可用、选中但焦点在右侧、当前、普通、普通）→ 资源管理全局 `0xC1810194 + 0x28` 指向的图像表（`0x10E41BFC`，每项 20 字节，ID `0..0x15E5` 共 5606 张 PNG）→ 图像数据。只有 `0x104ED4E2` 读这张表；ID 上限检查（`+0x14/+0x18`）是 `0xFFFF`。
- **图标组的两个读者**：`0x1045E578`（建立标签，字面量 `0x1045E958`）和 `0x1045F19C`（刷新标签，字面量 `0x1045F2B0`）。后者在右侧不是原厂 7 个标签页时，按 `+20` 给每个标签取第 6 张。
- **标签栏何时建立**：`0x103CEF94` 起的菜单打开流程每次都对页 1 调用 `0x1045E978` 和 `0x1045E602`（页面建立），按当时的页面描述建控件。QEMU 里 `0x102355EE(0xC182E688, 1)` 就是按 MENU；`0x1045F732` 只切换右侧页面，不重建标签栏。之前"晚改后重开菜单标签栏空白"是只用了 `0x1045F732` 重开造成的。
